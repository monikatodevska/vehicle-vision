# Training Models

All original training scripts, generators, custom losses, architectures,
ground-truth generation, and supporting analysis code are published under
[`archive/research/`](../archive/research/). Their data is kept separately.

## Maintained Training Workflow

The supported trainer keeps the original two-head inception detector, stride-8
output, categorical focal loss (gamma 2, unit class weights), and weighted
Smooth L1 regression loss. Regression ignores individual zero target values,
as in the original experiment, and sums rather than averages its penalties.
Defaults preserve raw grayscale pixels and a regression weight of 0.01.
Changing these conventions requires regenerating or verifying the targets.

Install `python -m pip install -e '.[ml]'`, then edit
[`configs/training.example.json`](../configs/training.example.json) for your
training and validation image/target folders. Paths are relative to the working
directory. Each image must have a target with the same relative filename stem.
Training and validation folders must be separate.

```bash
vehicle-vision validate-training --config configs/training.example.json --trust-pickle
vehicle-vision train --config configs/training.example.json \
  --output outputs/training/run-01 --trust-pickle
```

Only use `--trust-pickle` with files generated by your own trusted pipeline:
pickle loading can execute code. Alternatively set `target_format` to `npz`
and provide `.npz` files with `classification` and `regression` arrays; these
do not need the trust flag. Bounding-box CSV files are not training tensors.

Validation checks every image and target before training. It rejects missing
pairs, overlapping split paths, incorrect dimensions, invalid probabilities,
and non-finite values. Images are not silently resized against existing masks.
The trainer uses bounded float32 batches, keeps partial final batches, seeds
randomness, and records configuration and sample paths in `run.json`.
It saves `best.keras` by validation loss, `final.keras`, and `history.csv`.
Output folders must be empty to avoid overwriting previous experiments.
Optional `initial_model` and `initial_weights` configure compatible fine-tuning.

The implementation is in [`vehicle_vision/training.py`](../vehicle_vision/training.py),
with separate target loading and serializable losses. Automated tests include
legacy target parsing, loss-equation checks, a synthetic one-epoch run, and
saved-model reload. These checks establish pipeline functionality, not accuracy
on the unavailable proprietary dataset or bit-for-bit reproducibility across
hardware. Combined-output, wavelet, and weighted-mask variants remain historical.

## Generated Ground-Truth Files

The detector generators use filenames such as `image000001.txt`. Despite the
extension, these can contain sequential binary pickle objects rather than text.

The two-head and combined-output generators read, in order:

1. Classification tensor dimensions.
2. Flattened classification tensor values.
3. Regression tensor dimensions.
4. Flattened regression tensor values.

They reshape those values into `(rows, columns, channels)` tensors. The
combined-output pipeline concatenates the resulting tensors along the channel
axis. Classification-mask generators read the first two objects; their separate
weight-map files also store dimensions followed by flattened values.

Use the loader corresponding to the selected experiment. These generated targets
cannot be supplied directly to `vehicle-vision evaluate`, which expects bounding
boxes in a headerless CSV format. Load pickle targets only from your own trusted
generation pipeline.

## Running A Research Experiment

Before training, configure the selected script's image, ground-truth, validation,
weight-map, checkpoint, and output paths. Check its image naming convention,
input dimensions, normalization, class ordering, and selected loss/model.

Run from the research directory to preserve sibling imports:

```bash
cd archive/research
python FCN_SSD_anchorless_generator.py
```

This example identifies an entry point; it does not configure a dataset. The
scripts use historical TensorFlow/Keras APIs and experiment-specific imports.
The maintained package's current ML dependencies are not a verified training
environment for every archived variant. The source inventory records five
incomplete scripts with syntax errors; those scripts need repair before use.

The automated checks cover the maintained package and synthetic training.
They do not run archived experiments or validate the proprietary generated masks.
A small local training/validation run is needed
once matching images, ground truth, and the original experiment settings are
available.

## Future Demo Data

A few approved sample images and corresponding ground-truth files can later be
added under `examples/demo/`, which is tracked by Git. Full research data should
stay under the ignored `data/` directory or outside the repository. Keep binary
pickle masks separate from the evaluator's bounding-box annotations and document
the sample's source, dimensions, class mapping, and target-generation settings.
